# 1.3.110 主角更新不再误建NPC

## 修复

通用结算工具过去把chars描述为“这一轮出现过的人物”，而普通人物处理仅在NPC表按姓名查找；主角被交到chars时就会新增成NPC，后续补资料又给副卡补服装和人设。工具说明现明确chars仅NPC，主角更新放protagonist；程序侧同时在兼容归一后做人物归属整理，不只依赖提示词。

新模块`lib/settlement-identity.mjs`在生成与变量重算共用入口中工作：

- 明确主角编号、唯一准确姓名或主角／本人等明确指代，归回主角；只把指代当定位信息，不把姓名改成“本人”。
- 标准chars、角色／人物／npcs／NPC兼容容器、other和diffs中的命名主角路径均受同一整理。误投到NPC数组新槽位或整表的主角更新也能救回，原NPC整表／整条写入保护保留，不以移除主角为由清空名单或覆盖已有角色。
- 明确编号的同名NPC优先按编号更新。姓名、编号、旧名、主角标记互相冲突时保留原值，并保存拟写值诊断，不随便合并同名人物；明确NPC身份及不同身份资料可以保留真实同名NPC。
- 误投空人物模板不能抹去已确认的性别、生日、身份等资料，合法状态更新仍处理；明确protagonist容器的原语义不变。
- 误投的主角穿着沿用原槽位合并。不同通道的对象字段不重叠时可合并；同字段存在矛盾则保留旧值、给出冲突候选，不静默选最后一份，也不影响其他无冲突字段。
- 玩家维护的人设、NPC补档专用资料、内部账本和开关不能借误投通道改写。合法状态、衣物、资金等更新仍继续处理；拒绝项保留原始路径和拟写值。
- NPC编号匹配优先于姓名；明确旧名的改名仍走原曾用名与关系改名逻辑。

只做归属、兼容和冲突处理，不判断剧情该怎么写，不新增模型调用、重试、RPC或收费任务。

## 不做的事

不自动删已有角色，不改用户存档、旧差分或正文，不把历史数组下标当当前人物编号。历史seq9的NPC下标27现在已是另一个人，不能按旧下标删除。

衣物专用`complete_records`允许“主角也放chars”，仍由原验收器区分主角和NPC；这条合法协议不改。普通变量重算与资料重核原语义不变：前者回滚后重结算，后者增量补核并保留原差分；与规范protagonist回包对照，重复补核不会继续累积相同状态差分。

## 生效与验证边界

本次含宿主index及依赖模块改动，**需要完整退出并重启DSH后生效**。不是仅刷新前端即可。不代用户重启，不自动重算旧轮次。

54项专项覆盖最小误建回包、各兼容容器、主角指代、编号／同名冲突、衣物局部合并、双通道冲突、额外及深层路径、原整表保护、原值诊断、精确回滚，以及普通JSON、工具结算和两类变量重算的真实处理器。测试使用隔离VM／MapFS与模型桩，不等于已在真实模型或浏览器试玩。扩展回归按发布前独立源码／安装基线逐名比对；不删除旧断言或放开资料保护来凑全绿。
