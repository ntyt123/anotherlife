# 星途CP局势

## 使用

1. 开启星途模拟（主角“是否艺人”）。CP局势显示在星途页粉丝板块后。
2. 从新正文开始：明确归属主角与女性艺人/演艺从业者的公开嗑搭配、角色配对二创或零星留言，可以记录初生CP，不要求先有应援群或超话。普通同框、私下关系、计划及未发生的营业不自动成立CP。没有可靠人数依据时保持未知，面板显示“—”，不拿播放量或点赞量当CP粉人数。
3. 后续公开活动与微博实际互动在下一轮主结算统计，显示支持人数、本轮变化、热度、凝聚力、争议度、活动、讨论与趋势。
4. 微博主时间线支持点赞/取消点赞与转发；评论保留原入口，转发可在“我的微博”看到。操作成功保存后才成为事实，不额外独立调用CP模型。正文微博卡片中的具名点赞、评论等也能识别，只有点赞/转发总数时不会猜操作者。
5. 同一来源在微博和正文中只算一次。暂停星途时冻结CP；再次开启不补算关闭期间操作。旧缓存初次仅作为基线，不扫描旧档全文建立历史CP。

## 口径

- CP人数与艺人个人粉丝圈层口径不同，存在交叉，不机械累加进旧CP粉或全网粉丝。
- 正文有总数优先总数，只有增量或比例时据此计算。定性影响由现有结算模型估算，详情标注估算。人数下限零；没有相关事件不自动随时间涨跌。
- CP党成立不等于当事人恋爱，不改好感、婚恋或现金。网友讨论不构成新的独立事实。
- 每个有效活动包含讨论。模型漏回讨论时提供事实型兜底并提示，不自动重试付费请求。星途开启时结算工具要求返回CP数组，确无新事件用空数组；漏回字段会明确提示，未处理微博来源保留到后续正常结算。
- CP域可合并同次主结果、已声明结算工具及可见JSON中的cpUpdates/CP动态/CP更新，不读取额外思考，不覆盖普通世界或人物数据。相同事件补缺并去重；冲突数值的事件不采纳，重核冲突时保留原CP结果与回滚记录。CP候选字段、事件和应用数量会记录在本局结算日志中。
- 行动按钮只写入正文草稿，玩家发送、正文产生结果后才结算，不直接增加人数。

## 数据与回退

- 运行状态位于protagonist.cpState，使用英文内部字段；微博成功操作保存于weiboInteractions，绑定帖子、动作ID、轮次和星途启用代次。
- CP事件绑定正文seq/textVersion、微博来源ID；增量记录人数、话题和历史节点。删轮与重写随原回滚机制恢复；变量重算去重，漏回CP字段保留原结果与原逆向记录。
- 不直接修改旧档，不自动修旧历史。新宿主代码需完整重启DSH。

## 验证边界

自动化覆盖核心规则、真实宿主处理器、Map文件系统、模型桩和实际前端组件/回调；不等于真实模型文风与真实浏览器视觉已验收。
