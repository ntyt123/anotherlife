# 通用人生模拟 · 1.2.0

原生 Tavern SDK 2 插件，内部前后端协议 14。沿用 anotherlife 的全屏界面、原存储位置与既有功能，不是 Cordis 动态插件，也不是人物卡 MVU。

## 使用入口

- 主角：资料、任职、技能。技能从原主角区拆成独立标签，不另造重复入口。
- 经营：概览、设施、生产、人员、项目、财务。可管理多个单位、切换或查看全部单位。
- 系统：概览、任务、成就、对话。系统绑定和经营均可关闭，关闭不清空已有数据。
- 通用设定在创建阶段与设定页配置。新局可先生成通用资料，再逐条调整任职和技能；开始时复用已确认资料。游玩阶段不开放初值重套。

现代、古代、民国、学院是展示参考，其他题材用自定义资料。世界类型允许自定义或混合标签；模板不决定世界物理、不限制人物能力、不新增死亡、转世、穿越、世界实例或职业资格裁判。年龄显示不设旧的200岁上限。保留既有明星数据与评分、手机、神谕、图库、笔记、快照及导入导出。

## 人物与任职

NPC由程序分配持久actorId，姓名改变、人物排序变化不会把资料交给另一人物。删除角色后保留历史引用，不自动复活角色。新增角色仍遵守原具名与实际行动/对话建档规则；不因经营员工数量就创建一堆路人档案。

扩展资料按世界配置，如学院、学分、课程或其他字段；主角和NPC使用同一套角色引用。职务可记录组织、职位、职级、职责、权限、任离职时间和履历。职位变化由剧情确认，程序只记录前后履历，不制造通用职业经验、不自动判断“够不够资格晋升”。职位表可查看为参考，不是硬门槛。

## 三类技能

- 叙事成长：阶段或评价由剧情确认。
- 数值成长：初始经验、升级阈值或每级经验、已登记练习规则由程序计算。模型提交规则编号与次数，不直接改当前经验和等级。
- 固定能力：天赋、术法特性等只记录说明与效果，不强加等级条。

同一技能编号按actorId分别归属，NPC的同名技能不会覆盖主角。主角旧技能字段仅作兼容投影，不另算一套经验。旧附加字段保留；不能辨识的旧项保留原始记录，不凭空取名。创角编辑只打开当前一条，新增按钮在列表下方；游玩中由剧情维护。

## 经营与下一轮待办

推荐设施、升级方案和自定义需求均进入可见待办，不在点击时扣钱、开工或瞬间完成。待办可编辑、删除、清空；不同存档的输入与待办分别缓存。发送失败保留原局草稿；迟到回包不覆盖别局输入；同帧重复点击不会重复发送。

确定操作先预演，把成本、材料、工期、效果及阻塞原因交给正文。资金不足只阻止该项实际执行，不阻止继续写筹资或讨论。正文结算后按最新真实账户再次复核、原子落账；未执行项保留待办。最终输入含取消或暂缓等冲突意图时，会额外做一次逐项意图确认，不一刀切取消别的操作。

施工、生产规则在开工时冻结。未知成本、工期、工资或售价不当作免费或即时；显式为0的已确认规则仍可以计算。升级完成后的倍率只作用于后续时段。生产可批量计算并处理同资源回用；产出不自动变成销售。

多个单位独立记账；明确经过的时间推进既定运营，不因当前查看了哪家公司就暂停其他公司。同一人员的共享工时需明确workFraction，总量不超100%，校验也覆盖初值。单位间调拨资金和物资使用双边原子操作，不能复制库存。不同币种单位转账必须给明确exchangeRate，不自动猜汇率。

## 公司财务与原个人收支

**没有新增独立个人财务子系统、个人账本、个人钱包、个人结算页或个人结算服务。**原个人金钱、固定收支与手动月结入口保留。

公司收入、费用、库存和股权在各自经营账中。账面利润不等于个人收入；只有明确工资、分红、人员支付、出资或取款才以程序净变化连接原主角金钱。原个人现金更新只表达其他普通收支，不重复包含这些程序款项。已交经营模块结算的公司工资和分红不再重复写成个人固定收入；关联须依明确来源编号，不按金额相同猜重复。

- 已即时入账的销售/费用在期末只汇总，不重复加减。
- 结算先预览，再按同一预览确认；资料变化要求重新预览。
- 同一单位同一账期只记一次，常见中文月标签与ISO月标签归一。
- 已确认周期、工资与分红由程序计算；分币尾差分配后合计不超过宣派额。
- 财务只汇总已登记数据，不推测未提供的销量、售价或成本；明确未知金额会拒绝结算，不把它视为0。
- 创角重复整理同一单位更新初值，不当成营业收入，不复制一个新公司。
- 原个人正常月结保留；明确重设时间或跨极大年代时重置原收支基准，不把年份跳变自动当成千年连续领薪。

本版主角仍是原单一金钱字段，不新增个人多币钱包。个人与单位的直接款项按本局已确认记账单位处理；不要在没有明确换算事实时混用币种。

## 绑定系统

系统有名字、人格、主线指引、任务、成就、等级经验与独立对话记录，不复用神谕线程。对话可通过受控事件真正登记/取消任务；实际处理结果会显示，口头说“发钱”不会到账。正文可记录系统的主动台词或指引。

计量任务默认从发布时起累计，成就默认累计总量；也可明确配置。叙事任务需给达成依据。失败、过期、取消必须有依据；已发奖励不因一次失败事件被静默撤回。已发布规则冻结；金钱、系统经验、技能经验、物品和单位库存奖励均按领取记录防重。对话不直接完成任务、发奖、做交易；正式达成或领取才执行数值。

## 世界动态与模型费用

世界动态默认每3个成功新正文轮更新，可改间隔；开场、已停止的半轮、查看界面、手机、神谕、系统对话、维护不推进节拍。手动刷新可以立即请求。经营结构变化才触发对应推荐更新；普通收入流水不反复触发。两类背景任务能合批时合为一次。

后台结果绑定当前存档、世界资料与正文版本。旧世界内容不混入当前展示或提示词；编辑来源正文后旧版本资讯不再当当前资料。传闻与大事分开，大事显示是否确认。

资料准备、系统对话、手动刷新、自动世界动态和需要的推荐会产生正常文本模型费用。优先用已配置结算模型，未配置时用主模型；已配置模型失败不偷偷改模型重试。失败保留旧内容与尝试信息，不每轮追着重复收费；可主动重试。停止后迟到内容不覆盖旧结果。

## 回退、重核与存储

经营、技能、系统奖励与背景更新进入原差分链，删轮、重生成和快照可恢复；不另做“本轮变更”面板。通用模式的“重核最新一段资料”只修叙事资料，保留已确认的经营订单、资金与奖励账，防止重扣或丢订单。需要重做本轮已确认数值时，使用原轮次重生成/回退或快照，不把资料重核当任意改账。

仍用workspace/simulator-<gameId>.json和simulator-presets.json，不迁移官方saveGameData，不批量改旧档，不另建世界线列表。旧档不会只因升级就自动启用新经营或系统。导出、导入和快照包含本插件通用状态与持久人物引用，导入保持目标存档归属。

## 开发与生效

- npm run build:generic：同步独立界面工厂到原生client.js。
- npm run check：所有模块语法与工厂一致性检查。
- npm test：使用实际宿主/客户端源码、VM、内存文件系统与模型桩，**不调用真实模型**。

更新已加载的宿主需完全退出再重启DSH。本次不会自动重启、提交或推送。内部协议14会拒绝旧协议13宿主，避免新旧代码混跑。

验证边界：隔离测试不是浏览器DOM布局验收，也不代表真实模型一定遵守所有叙事与提取规则。未做实际游玩验证的原因是没有自动重启DSH，且用户未授权付费模型测试；具体测试与哈希结果记录在GENERIC-VERIFICATION.md。
