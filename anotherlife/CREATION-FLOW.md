# 开局流程 1.3.0

原生 Tavern SDK2，宿主／客户端协议15。六项快捷开局仍然只填写两份解析文本，不替玩家点击解析或开局。

## 新流程

1. 世界解析同时提交世界字段与玩法配置。结合世界文本及已有创角意向自动判断经营、绑定系统和展示类型；通用玩法只放在世界观设定内，可手动调整。世界类型不限制能力、寿命或剧情。
2. 创角解析提取主角、普通资产、权益与技能物品，然后自动接续关联人物、普通档案与衣着、任职／技能／经营／系统初值准备。所有这些请求都发生在解析阶段，不在开场正文之后补做。
3. 解析完成前按人物检查姓名、固定性格／背景和普通衣着；事业与资产不得空名，已声明亲属不得因空名册而消失。缺项显示未完成，不能进入正文。已确认非空设定优先，不为填满数据猜成交价、债务或估值。
4. 检查、编辑资料；修改后使用创建页“核对开局资料”。资料完整且通用初值缓存仍适用时只做程序核对，不重复请求模型。确实有缺项或需准备新的通用初值时会产生正常模型费用，不自动无限重试。
5. “进入正文”只验收确认后的资料，生成开场并做普通回合结算。开场不重新初始化、盘点人物或资产，不按身份重设现金，不调用资料补全／通用初值／初始后台刷新。后续新人物和剧情变化仍按普通回合处理。

## 数据与保护

- 新模块 `lib/creation-flow.mjs` 负责解析任务与验收；确认信息在 `simulation.creation`，与实际资料摘要绑定，不因客户端声称“已准备”就放行。
- 顶层实体资产、虚拟资产、关系和技能物品在创建阶段保存、可从完整JSON查看。预设保存使用同一份初始快照，不混用开局主角与当前轮人物；完整预设可直开，旧稀疏预设先载入、解析或补齐核对。
- 相关角色的普通衣着按最多四人一批生成，已有衣物名与固定档案优先。普通六槽包含头部／上衣／下衣／袜子／鞋子／饰品；可以确实未穿戴帽饰鞋袜，不能整套全空。已有私密字段不由这项普通资料任务新增或重写。
- 参考资料复用 `ctx.tavern.getCard({gameId})` 和原有衣柜读取器，只选普通衣着参考；不从文件读取卡片，不扩展身体或气味生成。
- 失败、漏项、重名、停止均不标完成；旧局迟到响应不回填新局，同帧重复解析不多发请求。真实草稿修改会阻止旧结果覆盖，程序首次补actorId不误判为业务修改。
- 保持原个人现金和跨月收支、手机、星途、经营与系统奖励的原有处理器；不添加独立个人财务系统，不迁移存档，不改已有游玩数据。完整预设加载时仅从已确认人物恢复派生联系人索引，不复制旧聊天、不调用AI补档。

## 验证边界

源与安装需分别执行 `npm run check` 和520项完整隔离回归（原487项及新增33项开局测试）。测试运行真实宿主处理器、客户端组件与点击回调，文件系统和模型均为内存桩；包括同次工具服装／文本人物资料分别验收、资产权益接收、开场零补档、跨局预设、停止与并发保护。

这不是浏览器DOM或真实模型实机验收。未自动请求付费模型、重启DSH、提交或推送Git。宿主更新后需完全退出并重启DSH；旧未完成草稿重新解析，或补齐后在创建页核对。旧游玩存档不自动回填。

本次源码备份、失败记录、部署清单及哈希结果位于 `temp/simwork/creation-flow-1793334804143`。原始159个存档JSON按本次基线保护，不沿用历史157个数字。

## 1.3.1：通用资料返回接收修复

- 修复模型只在block-end的tool-call完整块提交参数时被漏收的问题；最终参数覆盖对应delta而不是重复拼接，按工具id兼容末块index差异。
- 通用初值明确要求调用emit_simulation_setup；不支持工具时交完整JSON，不能以“已提交”等一句话代替。只发送该模块所需普通主角字段，不主动发送身体／私密／气味对象。
- 工具参数、正文、思考分别解码，兼容闭合JSON围栏及simulationUpdates包装，保留英文结构键；空或坏工具不能遮住同次其他通道的有效数据。
- 无效结构、错误字段类型和截断都不标准备完成；保留当前草稿，不自动重试付费请求。失败提示含模型短回复，轮次日志记录通道、长度、结束原因和参数结构摘要，不记录完整资料或凭据。
- 修复前用真实处理器／内存模型桩，以“名称delta＋最终完整工具块”复现“通用资料没有返回可解析结果”；修复后同一案例及创建页核对通过。真实失败日志有工具及普通文字返回，但此前未保存原始参数，不能认定截图那次唯一原因就是末块漏收。
- 新增24项专项；源与安装应分别跑544项完整隔离回归。不是浏览器DOM或真实模型验收。升级后完全退出并重启DSH，保留当前草稿，再点核对，无需重新创角；缺通用初值时会有正常模型请求。

## 1.3.2：开局普通贴身衣物漏项修复

1.3.0迁移初始生成时误用了只处理六槽的普通维护投影与验收，导致内衣／内裤既不在工具结构中，又可能从已返回名册中过滤掉，最后六槽齐全仍被标准备完成。本次修正整条开局链，不只是改一句提示。

- 新creation-wardrobe模块单独管理八槽：头部、上衣、内衣、内裤、下衣、袜子、鞋子、饰品。女性任务明确requiredSlots，缺贴身衣物不完成，也不以“未穿／暂无”冒充物品名。男性保持既有显示与适用约定，不强配女性款式。
- 名册保留、任务已有衣着、工具结构、生成规则、合并、验收、直接开局保护使用同一开局八槽定义；creation.version升级2。普通维护接口仍默认六槽，不全局改变旧协议。
- 补缺时保留已确认衣物名、非空品级、状态、简介及已有其他属性，不换外衣。已有通用初值仅缺贴身衣物时只补衣物，不重做职业／资产／系统；完整资料重核不请求模型。
- 本任务只生成适龄普通衣物，不新增身体、气味、沾染。婴幼儿按普通小衣和尿布等处理，儿童不套成人衣物；原气味AI末尾补空支路复用已有isAdultScentActor门槛，防止不适用人物进入成人机制。未改成年规则、库内容或AI开关。
- 当前仍在创建阶段：重启DSH后点核对开局资料，不用重新解析整个人物。已进入游玩时原有单角色穿着刷新入口仍保留；本次不会自动改写任何既有存档。
- 新增22项隔离专项，源／安装应分别执行566项完整回归。测试验证生成／投影／schema／保存／验收一致，旧确认不能放行、夹带字段不接纳、只补缺项与非空属性保护、名册已有值不重生成、不适用气味支路零写入。未调用真实模型或浏览器实机验收。

## 1.3.3：服装已齐但旧完成标记缺失导致误报

现场只读匹配截图同局：六名人物基础服装均通过hasReviewedWear，但story.dataCompletion.wardrobes对应标记全缺，保存着“6名角色基础服装待补齐”。1.3.0迁移初始生成时未同步旧维护标记，正文告警又只信旧标记，不是衣服丢失。

- 解析结束及完整预设进入正文前，按开局八槽实际验收结果派生同步完成标记，清过期衣物错误，保留其他补全元信息。
- 旧标记缺失但现有基础服装合格时，不列入普通补全任务，也不为核实同值衣物额外请求模型。真正缺衣物或字段不合格的未完成项仍会提示。
- 状态返回统一整理已有的服装告警，老存档重新打开面板即可按当前衣物重算，不必补衣物、重生成开场或再走AI核对。整理仅作用于服装部分，保留同条非服装内容和独立账务等提示；不对本来没服装告警的历史正文新增提示。新增整理不写服装／剧情、不新增存档保存或模型请求。
- 新增13项专项，源／安装各执行579项完整隔离回归。原566中一条保衣测试明确指定原请求目标，避免完整人物不再入任务后索引变人；一条旧“完整衣物还请求模型”预期改为零请求，补齐独立固定档案前置，不关闭其他真实缺项任务。
- 六人复现场景验证getState零模型且不修改持久数据、普通操作返回不复活旧警告、其他告警保留、缺项仍报警、解析标记同步与跨局预设正常结算后无误报。不是浏览器DOM或重启后的真实模型验收。升级后需完全退出重启DSH，再打开原局面板；无需重复生成衣物。
